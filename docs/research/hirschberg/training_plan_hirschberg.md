# Training Plan Hirschberg - Awaiting Approval

Date: 2026-10-03

Status: proposed only. No training has been started.

## Recommendation

Do not train a production candidate yet. The current dataset should only support a research baseline after approval. The safest first approved run is approach A: geometry/interpretable features plus calibrated Logistic Regression and Random Forest baselines. Approach C can be explored only if the feature extraction coverage is acceptable after the environment is repaired. Approach B, pure CNN transfer learning, is not recommended on the current `harschberg_data_detect/` alone.

Reasoning from audit:

- Current trainable dataset has 136 images: esotropia 55, exotropia 40, normal 41.
- All images are 224x224 crops, not phone full-face uploads.
- No participant IDs are available.
- Existing filter report shows 72.9% rejection and only 2/502 FaceMesh landmark detections.
- Prior detector benchmark on an older 696-crop manifest showed only 4.45% joint pupil+reflex coverage.

## Approach Choice

### A. Geometry features + classical ML

Chosen as the first baseline if approved.

Features:

- Per-eye reflex offset from iris/pupil center, normalized by iris diameter/radius.
- Left/right asymmetry and disagreement.
- Quality features: reflex count, reflex area, pupil/reflex detector status, brightness, blur, crop geometry.
- Optional safe appearance summary features only if they do not dominate geometry.

Models:

- Logistic Regression with class weights.
- Random Forest or HistGradientBoosting as nonlinear comparison.
- Probability calibration using validation-only temperature scaling or sklearn calibration.

Why:

- More explainable for Hirschberg.
- Better suited to small data.
- Easier to reject low-quality images when geometry is missing.

Risk:

- Current detector coverage may be too low; if offsets are missing too often, model quality will be poor.

### B. CNN transfer learning

Not recommended now.

Why not:

- 136 crop images is too small.
- Participant leakage cannot be controlled.
- CNN can learn crop/source/brightness artifacts.
- It will not solve the full-face phone-upload domain shift.

### C. Combined A + B

Possible later, after more data or a recovered larger manifest.

Use only if:

- Working environment is repaired.
- A reproducible manifest has at least several hundred clinician-confirmed images.
- Eye crops are generated by the same preprocessing planned for backend inference.
- Validation shows Grad-CAM attends to eyes/reflexes rather than image borders/source artifacts.

## Data Split

Preferred:

- Group split by participant ID, stratified by class.
- Test set held out once and never touched until the end.

Current fallback if no participant IDs:

- Use conservative group IDs from class + original filename stem.
- Deduplicate/near-deduplicate before splitting.
- Use repeated stratified k-fold for model selection, but clearly mark results as leakage-risk estimates.
- Do not claim clinical generalization.

## Class Imbalance

Current accepted data is mildly imbalanced. Use:

- `class_weight="balanced"` for Logistic Regression / Random Forest.
- Macro-F1 and per-class recall for selection.
- Threshold tuning only on validation folds, prioritizing esotropia/exotropia recall.

Avoid oversampling unless the approved split is stable; with only 136 images it can amplify near duplicates.

## Augmentation

Allowed for later CNN/crop robustness:

- Horizontal flip only if labels are transformed correctly or if using binary strabismus-vs-normal; for 3-class eso/exo, naive flip can invert direction and must be handled carefully.
- Rotation +/-5 to 10 degrees.
- Mild brightness/contrast changes.
- Mild scale/translation that keeps both eyes visible.

Do not use:

- Strong blur.
- Cutout/random erasing.
- Crops that remove eyes.
- Strong color shifts.
- Synthetic noise that creates fake corneal reflexes.

## Metrics

Primary:

- Recall for esotropia.
- Recall for exotropia.
- Binary sensitivity/specificity for strabismus vs normal.

Secondary:

- Macro-F1.
- 3-class confusion matrix.
- ROC-AUC for strabismus vs normal if probabilities are available.
- Calibration error / reliability plot if displaying percentages to users.

Model selection should favor not missing strabismus cases, but false positives must be tracked because this is a screening tool shown to users.

## Probability Calibration

Use validation-only calibration:

- Prefer temperature scaling or isotonic/Platt calibration depending on model family and validation size.
- Report calibration curves and expected calibration error.
- Do not display raw uncalibrated softmax as a medical probability.

## Verification

Before accepting any candidate:

- Review false negatives for esotropia/exotropia.
- Review false positives among normal.
- For CNN/combined models, run Grad-CAM or saliency checks.
- Confirm predictions change sensibly when reflex/iris geometry changes.
- Confirm low-quality/missing-reflex images stop at `quality_ok=false` and do not produce class probabilities.

## Fallback If Data Is Not Enough

Release only an explainable research/quality measurement path:

- Quality gate: face detected, both eyes visible, flash/reflex visible in both eyes, blur/brightness acceptable.
- Geometry output: per-eye reflex offset normalized by iris/pupil diameter.
- No CNN and no clinical class claim until real protocol data and labels are available.
